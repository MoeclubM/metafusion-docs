## 2026-09-19 — 站内通知系统（目录服务侧收件箱）

平台此前**没有任何通知系统**：被回复、被收录、审核结论与导入完成都无处可见。现在收件箱落在目录服务
（五类事件里四类的产生端就在它这一侧，前端 `/api` 的主系统也是它），并补上以下事实：

- **读取端**（都需登录，且**只对自己可见**）：收件箱 `GET /api/notifications`（`items` / `total` / `unread`，
  按最近活动倒序，`limit` 默认 20 上限 100）、未读角标 `GET /api/notifications/unread-count`（只做一次计数，
  300 / 分钟）、标记已读 `POST /api/notifications/:id/read` 与 `POST /api/notifications/read-all`。
  请求里**没有 recipient 参数**——收件人恒为令牌持有者；对别人的通知标记已读与对不存在的 id 一样回
  `404 not_found`（不用 403/404 的差异泄露他人通知的存在性）。
- **五类事件**：`comment.replied`（有人回复了你的帖子，或你参与过讨论的条目又有新评论）、
  `entity.included`（你的作品被发行收录或被集合收录）、`entity.review_approved` / `entity.review_rejected`
  （审核通过 / 驳回，通知条目创建者）、`import.completed`（导入完成回执，发给发起人自己）。
- **聚合**：同一收件人同一聚合键的多条事件**只保留一行**（`count` 记录合并了多少条），
  且该行会重新变为未读；上游重投同一事件（超时重试）不会把一条回复算成两条。
- **保留期**：建议 180 天，**当前不执行清理**（清理要配套产品决定；读取端不做任何服务端删除）。
- **跨服务写入**：只有“评论被回复”来自互动服务，它按 `POST /api/notifications/internal` 投递
  （两个凭据：共享密钥 `INTERNAL_API_TOKEN` + 终端用户令牌）；密钥未配置时该端点回
  `503 internal_api_disabled`、互动侧不投递——评论与回帖**照常成功**，只是不产生通知。
- **`/notifications` 页面**：顶栏常驻铃铛入口 + 未读角标（不轮询：挂载、窗口重新可见、以及标记已读后各取一次），
  列表页空态与失败态分开（失败只给失败文案与重试，不把“取不到”讲成“没有通知”）。
## 2026-09-18 — PAT 落地与限流响应头：认证、文档入口与设置页口径

账号服务开始签发个人访问令牌、目录服务接入它的内省判定，以下说法随之作废并改写：

- **第三种凭证（PAT）**：明文前缀 `mfp_`，设置页自助创建 / 列出 / 吊销（`/api/auth/tokens*`），
  明文只在创建响应里出现一次、之后取不回；`scopes` 是**权限码**（创建者必须自己持有，超出即拒绝），
  空数组 = 仅身份无任何权限；每账号最多 10 张未吊销令牌；吊销、到期与权限收回在目录侧**最长 60 秒**生效
  （下游缓存内省结果 60 秒）。无效 / 已吊销 / 已过期统一 `401 invalid_token`，账号服务不可达回
  `503 auth_unavailable`；**没有 `X-API-Key` 认证方式**。见 [认证与凭证](/api-auth)；
- **交互式文档入口不再是公开入口**：`/api/docs`（Scalar）与 `/api/swagger`（Swagger UI）移到
  `catalog.lifecycle.manage` 之后（页面与随二进制自托管的脚本、样式同一道闸门），
  接入方要读契约看**公开**的 `GET /api/openapi.json`（与 `GET /api/version` 同列公开面）；
- **实例设置**：补上"账号管理台的「实例与设置」只读、写入走 `PUT /api/admin/settings`"这一事实，
  不再把管理台写成改设置的入口；
- **限流响应头改为事实**（主仓 `fbd7d6b`）：目录服务的路由级限流在**每个响应**上发
  `X-RateLimit-Limit` / `X-RateLimit-Remaining` / `X-RateLimit-Reset`（超限的 `429` 也带，另带 `Retry-After`），
  此前文档（与四语字典）一边承诺这组头、一边又说服务端不发；同时补全限流路由表里漏掉的
  `GET /api/catalog/entities/stats`（120 / 分钟，需 `catalog.lifecycle.manage`）。
  网关与账号 / 互动 / 存储自身限流不发这组头。

## 2026-09-16 — 站点内容与政策页按实现校正

逐条把首页、核心理念、服务条款、隐私、版权、联系、FAQ 与更新日志里的可核实断言拿去核代码、路由、迁移与线上响应，收掉无出处或已过时的说法：

- **域名口径**：适用范围由 `metafusion.io` 改为实际部署域 `findverse.cc`（服务条款页）；
- **注册要求**：用户名与密码为必填（用户名 2–80 字符、密码 12–72 位），邮箱选填，留空时按「用户名@站点域名」生成占位地址（账号服务 `Register`）；
- **限流**：补齐实际的三层——账号服务认证写入类接口 15 次/分钟、目录服务按路由 120 / 60 / 10 次每分钟分档、网关按前缀 30 r/s 与 5 r/s；`/api/storage/` 由「不限流」改为实际的 30 r/s（burst 100）；并说明只有目录服务的路由级限流带 `Retry-After`；
- **邀请链**：隐私政策里的 `invited_by` 改为实际的 `auth.invites` + `auth.invite_uses` 两表；
- **账号权利**：设置页当前只提供资料查看与改密码，资料更正与账号注销需联系站务（不写自助入口）；
- **版权页**：删掉「下载入口展示版权与合规提示」这一未实现的说法；`robots.txt` 由「禁止直链索引」改为实际的「允许抓取公开页面，靠鉴权与限流保护资源」；
- **实体骨架名称**：理念页的八类改与 `definitions.kinds` 一致（主体 / 集合 / 作品 / 内容单元 / 内容表达 / 发行版本 / 载体 / 收录位置）；
- **公告板块**：由「不开放日常发帖」改为引导口径（该板块当前未做发帖限制，编目与合规问题请走 `bug_report`）。

## 2026-09-16 — 文档按实现校正

概览、快速上手、FAQ、社区指南与首页文案按代码实现重新核对，收掉一批从未落地的能力表述：

- **认证**：不再出现个人访问令牌（`mfp_` 前缀）与 `X-API-Key`；程序化接入统一以会话令牌（`mf_session` Cookie 或 `Authorization: Bearer`，访问令牌 15 分钟 + 服务端会话 24 小时）与 OAuth 2.0 授权码为准；
- **检索**：统一为 `GET /api/catalog/entities` 的 `q`（标题与译文的子串匹配），不再宣称 MusicBrainz 兼容 API 层、独立检索端点、罗马音匹配、即时联想或分词与相关度排序；分页为 `limit` / `offset`；
- **限流**：改为实际口径——账号服务对认证写入类接口按 IP 15 次/分钟，目录服务按 IP + 路由做路由级限流（120 / 60 / 10 次每分钟分档），网关按前缀限流（`/api/` 与 `/api/catalog/` 30 r/s、burst 50，`/api/auth/` 与 `/api/setup` 5 r/s、burst 10，`/api/storage/` 30 r/s、burst 100）；超限 `429`，目录服务的路由级限流带 `Retry-After`；不再声称按登录状态区分的全站配额或 `X-RateLimit-*` 响应头；
- **互动服务**：板块按服务端实际播种的六类（站点公告、闲聊杂谈、求助答疑、考据评注、反馈与建议、评论专用）描述，删除不存在的私聊功能与未实现的发帖频控承诺；
- **资源**：下载受绑定实体可见性约束、只分发原始文件（不做转码与在线播放），与本页 2026-08 早期的记录一致；
- **权限**：能力表按权限码对齐（实例设置、权限组与用户、邀请码、OAuth 客户端、类型与关系定义、货架与外部库规则、编目审核与合并）。

> 这一段里的"**不再出现个人访问令牌（`mfp_` 前缀）**"只描述当时状态：PAT 随后实现并接入，见 2026-09-18 一条。
> 同段的"不再声称 `X-RateLimit-*` 响应头"同样只反映当时服务端：目录服务的路由级限流随后真的发出了这组头（`fbd7d6b`，见 2026-09-18 一条）。
