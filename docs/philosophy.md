# 核心理念与定位

## 开放元数据

MetaFusion 致力于构建开放、规范的多媒体资源与元数据共建库：

- **高度结构化**：按 LRM 分层思想落成固定八类实体骨架（主体 Agent / 集合 Collection / 作品 Work / 内容单元 ContentUnit / 内容表达 Expression / 发行版本 Release / 载体 Medium / 收录位置 Track），类型与字段由服务端动态定义驱动。
- **稳定可引用**：每条实体具备固定 UUID 与版本修订历史，便于跨平台引用与元数据集成。
- **开放互联**：提供标准 REST API，支持个人应用、社区工具与 AI Agent 无缝调用。

## 社区共建与考据精神

词条创建与编辑遵循可追溯与可考据原则：

- **版本追溯**：每次写入都会在 `catalog.revisions` 留下带快照的修订行，可对比历史；实体没有一键回滚端点，需按历史内容重新写入（动态定义版本可以回滚）。
- **实体合并**：针对重复收录的词条，支持通过合并流程保留关联关系与贡献历史。
- **来源可信**：写入必须带 `edit_note` 与至少一条 `sources`（`kind` / `citation` / `url`），缺一即被服务端拒绝。

## 存储与分发

- **内容寻址**：文件的身份是 SHA-256，同一份内容全库只登记一次，命中即秒传，不重复占空间。
- **受控原档分发**：上传与绑定归存储服务，下载按「上传者与审核者直通，其余人看绑定实体是否可见」判定；预签名地址默认 120 分钟过期。
- **明确不做转码**：没有预览切片、低码率流或波形图；需要预览时由客户端拿原档自行处理（见 [资源上传与下载](/upload-download)）。

## 邀请机制

邀请机制用于保障社区建设质量与合规运营：

- 维护健康的社区交流环境与高质量的元数据维护梯队；
- 提供清晰的邀请追溯链，保障资源贡献的可信度；
- 后台可动态开启或关闭公开注册与邀请码要求。
