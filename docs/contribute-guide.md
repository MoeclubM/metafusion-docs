# 资源收录与投稿标准

为了让全站资源长期可用，MetaFusion 对投稿的元数据与媒体文件制定了以下标准。
平台**只保存与分发原始文件**，不做转码、切片或预览流（见 [资源上传与下载](/upload-download)）。

## 1. 投稿流程

1. **查重确认**：先在检索里查作品与发行版，避免重复录入
2. **填写元数据**：从「新建条目」进入编目枢纽（`/contribute`）按层级打开录入向导（`/new?kind=...`），或在已有条目的编辑入口填写题名、发行日期、标签与来源
3. **上传资源**（可选）：把原始文件交给存储服务——服务端流式上传，或分片直传对象存储
4. **提交**：有编辑权限的成员可直接发布条目；没有该权限时只能存草稿或提交待审（`pending_review`），
   由管理团队审核后发布

条目本身与文件是两件事：元数据写入走 `/api/catalog/entities`，文件与绑定走 `/api/storage/*`。

## 2. 文件格式建议

| 媒介类型 | 推荐格式 | 说明 |
|---|---|---|
| **无损音频** | FLAC、ALAC、WAV（16/24-bit） | 原档保存与分发，不做转码；试听由下载方自行处理 |
| **有损音频** | MP3（320 kbps）、AAC（256 kbps+） | 体积敏感的原声或广播剧 |
| **视频影像** | MP4（H.264/HEVC）、MKV | 原档保存与分发，不做切片或预览流 |
| **电子书刊** | EPUB、PDF、CBZ/CBR | 漫画、画集与小说文献 |
| **封面图片** | JPG、PNG、WebP | 优先权利方/出版发行方提供的高清原图，保持原始比例、无水印，并核实再利用许可或明确授权；来源官方不自动代表可转载，权利不明时不要上传 |

上传时客户端本地算 SHA-256：库里已有同一份内容即秒传（内容寻址），不重复占空间。

格式建议是编目口径：服务端不按扩展名或 MIME 拦截，只校验声明的大小与回读重算的内容哈希。

## 3. 条目状态

| 状态 | 含义 |
|---|---|
| `draft` | 草稿，仅创建者与持 `catalog.lifecycle.manage` 者可见 |
| `pending_review` | 待审，仅创建者与持 `catalog.lifecycle.manage` 者可见 |
| `published` | 已发布，公开可见（发布要求至少一条翻译行） |
| `deleted` / `merged` | 已停用 / 已合并，仅创建者与持 `catalog.lifecycle.manage` 者直读；合并的用 `/resolve` 跟随 |

发布后要大幅重写时，先下架再改：由持 `catalog.lifecycle.manage` 的成员用 `POST /api/catalog/entities/:id/unpublish` 把条目下架回 `draft`，改完按正常流程重新发布。

下架只接受 `published → draft`，要带 `expected_version` 与修改说明 / 来源；下架会在修订历史里留痕。

收到审核意见时，按意见补齐来源或修正结构后再提交。修正他人已发布条目需要编辑权限；
合并、停用与下架需要 `catalog.lifecycle.manage`。

## 4. 记录与权限

- 每一次写入都会在 `catalog.revisions` 留下修订行（操作者、说明、来源与快照），
  用 `GET /api/catalog/entities/:id/revisions` 查看
- 编辑、审核、导入、定义管理等能力都以权限码授予（由管理团队按权限组分配），
  不是可自行申请的头衔；当前没有独立的「贡献值」排行榜接口
